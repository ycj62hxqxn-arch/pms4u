System Design

Constitutional Authority Flow

Every execution request traverses this chain. No step is skipped. Each gate produces a signed record.

👤
User / Agent
Request originates from user, API caller, or AI agent. No authority assumed.
🚦
QGED Gate
Authority validated. Returns ALLOW or BLOCK. Runtime raises RuntimeError on BLOCK.
⚖️
Admissibility
State, risk class, consequence domain, and signer threshold evaluated.
📋
Evidence
Signed receipt created. SHA-256 hash chained to previous event. Evidence ID issued.
🔗
Ledger Append
Immutable JSONL append. Correlation ID, actor, verdict, and hash stored.
🔁
Replay / Audit
Any event can be replayed, projected, or verified via crypto verification endpoint.

Engineering

Backend Services — File Map

Six distinct service packages. Each has a defined boundary role in the authority chain.

governance-core/

Constitutional Execution Runtime

FastAPI service. The production authority runtime. Handles transitions, authority scopes, crypto verification, websocket event bus, and replay.

  • src/api/main.py — FastAPI app + QGED authority scope enforcement
  • src/runtime/replay_engine.py — Replay and projection rebuilder
  • src/crypto/signer_registry.py — Detached signature verification
  • src/db/ledger.py — Event-sourced ledger (SQLAlchemy)
  • src/api/websocket_bus.py — Real-time event bus
  • authoritative_ledger.jsonl — 13 live evidence records
execution-proof-stack/

Constitutional Gateway (MVP)

Minimal proof gateway. Evaluates admissibility, enforces execution boundary, issues constitutional verdicts, and records evidence.

  • constitutional_gateway.py — Evaluate → Admissibility → Verdict → Evidence
  • admissibility/admissibility_engine.py — Risk, state, dependency checks
  • boundary/enforcement.py — BoundaryViolation raises FREEZE
  • ledger/evidence.py — Evidence record creation
  • failure/failure_constitution.py — Failure type classification
  • demo_financial_gateway.py — Financial domain demo
carshunter_app/

CARSHUNTER Automotive Governance

Flask application. Governs automotive trade transitions via the shared governance runtime. Includes state machine, receipts, and ledger.

  • governance/state_machine.py — 8-state transition graph
  • governance/authority.py — Authority verification
  • governance/receipts.py — Signed execution receipts
  • governance/evidence.py — Evidence record creation
  • governance/freeze.py — Constitutional freeze
  • ledger/replay_lineage.py — Lineage reconstruction
operations-core/

AegyptenHautnah FastAPI Backend

Tourism operations backend. Lead registry, social agent, and governed intake routing for aegyptenhautnah.com.

  • lead_registry/ — Lead capture and governance routing
  • social_agent/ — Telegram/WhatsApp intake agent
  • API: api.aegyptenhautnah.com
governance-sdk/

Cross-Service SDK Contracts

Python package. Shared types, states, receipts, and UI contracts used by governance-core, carshunter_app, and Next.js API adapters.

  • governance_sdk/states.py — HuntState enum + ALLOWED_TRANSITIONS
  • governance_sdk/receipts.py — ExecutionReceipt dataclass
  • governance_sdk/ui_contracts.py — GovernanceEventUI, TraceViewerProps
  • governance_sdk/exceptions.py — IllegalStateJump
app/api/ + server.js

Next.js API Adapters + YAI Server

Thin Next.js API routes. Business logic stays in governance-core. YAI OpenAI server for the operator assistant layer.

  • app/api/agent/ — Agent API adapter
  • app/api/yai/ — YAI Local operator API
  • scripts/yai-openai-server.mjs — YAI OpenAI proxy server
  • scripts/start-yai-local-with-key.sh — Local YAI launcher

governance-sdk — Cross-Service Contracts

Shared Python package. When contract fields change, update UI normalizers and API responses together.

8-state enum: INTAKE → VERIFIED → COMPLIANCE_PENDING → PAYMENT_CONFIRMED → GOVERNANCE_REVIEW → EXPORT_APPROVED → EXPORTED → ARCHIVED
ALLOWED_TRANSITIONS
governance_sdk/states.py
Dict mapping each state to its valid successors. Illegal jumps raise IllegalStateJump.

Signed receipt dataclass. Carries verdict, correlation_id, evidence_id, hash, timestamp.

The Principle — Four Questions

1. Who has authority?
2. Is execution admissible now?
3. Can execution be interrupted?
4. Can the consequence be independently verified?

If the answer to any is unknown, execution does not proceed. Engineering constraint, not policy statement.
